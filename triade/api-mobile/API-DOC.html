API Mobile — Documentation Technique

Back-end PHP du système T.R.I.A.D.E v4 — Endpoints consommés par l'application mobile TriadePhone.

📁 /triade/api-mobile/ 🔐 Auth : Session PHP 📦 Format : JSON (UTF-8) 📅 Mis à jour : Lundi 8 juin 2026
Convention d'authentification. Toutes les routes (sauf etablissement.php et login.php) nécessitent une session PHP active ($_SESSION["connecte"] === true). Un code 403 est retourné sinon. Les routes réservées aux enseignants vérifient en plus $_SESSION["membre"] === 'menuprof'.

Configuration

GET get-phone-version.php Public

Version de compatibilité TRIADE-PHONE

Retourne la version de l'API attendue par ce serveur TRIADE. Appelé par l'application mobile au démarrage pour vérifier la compatibilité avant toute authentification. Endpoint public — aucune session requise.

Fichier source : common/config-phone.php — définit la constante API-PHONE-VERSION.
Incrémenter cette valeur à chaque rupture de compatibilité entre le serveur TRIADE et l'application mobile (nouveau endpoint requis, changement de format de réponse, suppression de fonctionnalité…).
Réponse (200)
{ "version": "4.0" }
Comportement côté client (SplashScreen.js). La constante APP_PHONE_VERSION = "4.0" est définie dans l'application. Au démarrage, si l'URL serveur est connue, l'app compare les deux versions :
  • Versions identiques → flux normal.
  • Versions différentes → Alert proposant de continuer quand même ou de fermer.
  • Endpoint absent (ancienne installation) → silence, compatibilité préservée.
GET

codeQR.php

/triade/codeQR.php

Endpoint de configuration automatique de l'application TRIADE-PHONE par scan de QR code. Supporte deux formats selon le paramètre cd.

Format QR mobile (JSON)

Déclenché quand cd contient 6 champs séparés par des virgules se terminant par QR.
Ce format est généré par triade-phone.php via $text="$protocol,$adresseurl,$compte,$nom,$prenom,QR".

Paramètre GETTypeDescription
cdstringDonnées QR au format protocol,host/path,compte,nom,prenom,QR

Exemple :

GET /triade/codeQR.php?cd=http,mon-ecole.fr/triade/,4,Dupont,Marie,QR

Réponse JSON :

{
  "server": "http://mon-ecole.fr/triade/",
  "nom":    "Dupont",
  "prenom": "Marie",
  "profil": "4"
}
ChampDescription
serverURL complète du serveur Triade (avec slash final)
nomNom de l'utilisateur (depuis la session serveur)
prenomPrénom de l'utilisateur
profilType de compte : 1=Élève, 2=Parent, 3=Enseignant, 4=Direction, 5=Vie scolaire

Format badge / code-barres (texte brut)

Déclenché quand cd est un identifiant numérique. Retourne le nom et prénom de la personne en texte brut, ou Error si le compte est inactif.

GET /triade/codeQR.php?cd=42   →   "Dupont Marie"

Comportement côté application mobile

TRIADE-PHONE scanne le QR code affiché dans triade-phone.php. Le contenu scanné peut être :

  • Le texte brut protocol,host,compte,nom,prenom,QR
  • Une URL complète http://serveur/codeQR.php?cd=protocol,host,compte,nom,prenom,QR

Dans les deux cas, l'app extrait le paramètre cd, parse les champs et pré-remplit le formulaire de connexion (serveur, profil, nom, prénom). L'utilisateur n'a plus qu'à saisir son mot de passe.

POST login.php Public

Connexion

Authentifie un utilisateur et ouvre la session PHP. Supporte tous les profils : élève, parent, enseignant, direction et vie scolaire.

Mapping profil → membre. Le paramètre profil est converti en chaîne membre avant l'appel acces() : 1→eleve, 2→parent, 3→enseignant, 4→administrateur, 5→vie scolaire.
Paramètres POST
ParamètreTypeRequisDescription
profilstringRequis1 = élève, 2 = parent, 3 = enseignant, 4 = direction, 5 = vie scolaire
nomstringRequisNom de famille
prenomstringRequisPrénom
mdpstringRequisMot de passe
a2fstringOptionnelCode 2FA si activé
Réponse — Succès (200)
{
  "code":     "200",
  "message":  "Authentification réussie",
  "id":       "42",
  "idclasse": "5",
  "membre":   "menueleve"
}
Réponse — Erreur
// 401 — identifiants incorrects
{
  "code":    "401",
  "message": "Erreur de connexion"
}

// 401-A — 2FA requis
{
  "code":    "401-A",
  "message": "Authentification supplémentaire nécessaire"
}

// 403 — compte désactivé (avant acces())
{
  "code":    "403",
  "message": "Votre compte est désactivé. Veuillez contacter l'administration de votre établissement."
}
Blocage compte désactivé. Avant l'appel à acces(), le serveur vérifie directement en base si le compte est désactivé et retourne HTTP 403 avec code: "403" pour permettre au client d'afficher un message explicite. Champs vérifiés : compte_inactif dans tria_eleves (profils 1 et 2), offline dans tria_personnel (profils 3, 4, 5). Cette vérification précède acces() car cette fonction bloque aussi les comptes inactifs mais sans code de retour différencié. Côté client (triadeApi.js), l'appel login utilise skip403: true pour que le 403 ne soit pas intercepté par le handler global de session expirée — le code '403' est traité explicitement dans OnboardingScreen.js.

Notifications push

Infrastructure. Les tokens Expo Push sont stockés dans tria_push_tokens (colonnes user_type, user_id, token, updated_at). Un même utilisateur ne possède qu'un token à la fois (contrainte UNIQUE KEY unique_user(user_type, user_id)). Les notifications sont envoyées via l'API Expo (https://exp.host/--/api/v2/push/send). Elles ne fonctionnent pas dans Expo Go SDK 53+ — un build de développement ou de production est requis.

Couverture mobile + web. Les API mobiles (save-absences.php, save-sanction.php, save-retenue.php) déclenchent le push via api-mobile/push_helper.php. L'interface web Triade passe quant à elle par les fonctions create_absent(), create_retard(), create_discipline_sanction() et create_discipline_retenue() de librairie_php/db_triade.php, qui appellent directement notifyEleve() depuis librairie_php/push_notif.php — garantissant que toute saisie, quelle que soit son origine, déclenche la notification push. Les messages envoyés via envoi_messagerie() (cas simple, brouillon=0) sont eux aussi pushés depuis db_triade.php ; la notification est envoyée au user_type / user_id du destinataire.

GET get-unread-count.php Session

Nombre de messages non lus

Retourne le nombre de messages non lus dans la boîte de réception de l'utilisateur connecté. Interrogé toutes les 30 secondes par l'application pour mettre à jour le badge sur l'icône Messagerie.

Réponse (200)
{ "count": 3 }
Requête SQL. SELECT COUNT(*) FROM tria_messageries WHERE brouillon='0' AND type_personne_dest='$type' AND destinataire='$id' AND lu='0' AND (repertoire IS NULL OR repertoire='0'). Utilise type_personne_dest (type du destinataire) et non type_personne (type de l'émetteur).
GET get-viesco-count.php Session

Compteurs vie scolaire

Retourne le nombre d'absences, retards, sanctions et retenues de l'élève ou du parent connecté pour l'année scolaire en cours. Interrogé toutes les 30 secondes par l'application (conjointement avec get-unread-count.php) pour détecter de nouvelles entrées et afficher le badge ! sur l'onglet Vie Sco. Retourne des zéros pour tout profil autre qu'élève (1) ou parent (2).

Réponse (200) — élève / parent
{
  "total":     7,
  "absences":  3,
  "retards":   2,
  "sanctions": 1,
  "retenues":  1
}
Réponse (200) — autre profil
{ "total": 0, "absences": 0, "retards": 0, "sanctions": 0, "retenues": 0 }
Logique de détection. Le client compare total avec la valeur précédente (prevViescoTotal). Si le total augmente, un badge ! est posé sur l'onglet et un toast apparaît en haut de l'écran. Le badge est effacé à la première consultation de l'onglet Vie Sco (onVieScoPress). Les profils 1 et 2 (élève et parent) partagent le même id_pers = elev_id, d'où la compatibilité directe avec les fonctions affAbsence(), affRetard(), etc.

MSN / Chat instantané

Principe. Le module MSN TRIADE est une messagerie instantanée locale entre tous les utilisateurs de l'établissement (personnel, enseignants, élèves, parents). Les messages sont stockés dans tria_messages et les comptes dans tria_users.

Authentification bridge. Ces endpoints créent automatiquement un compte MSN lié à la session TRIADE via le couple id_pers + membre (identifiant composite unique). L'email synthétique {id_pers}_{membre}@msn.triade est dérivé de ce couple. L'utilisateur n'a pas de mot de passe MSN supplémentaire à saisir. Appeler msn-init.php en premier pour initialiser $_SESSION['unique_id'] — les autres endpoints en dépendent.

Schéma tria_users. La table comporte deux colonnes ajoutées : id_pers INT et membre VARCHAR(50), avec contrainte UNIQUE(id_pers, membre). Les comptes créés avant migration ont ces colonnes à NULL — elles sont mises à jour automatiquement lors de la prochaine connexion via msn_auto_init.php.

Sécurité création. Un compte ne peut être créé que si au moins un identifiant exploitable est présent : email valide ou couple id_pers + membre. Les comptes sans unique_id valide (NULL ou 0) sont purgés automatiquement à chaque chargement de la liste des contacts.
GET msn-init.php Session

Initialiser le compte MSN

Crée ou vérifie le compte MSN lié à la session TRIADE courante, puis positionne $_SESSION['unique_id']. À appeler une fois avant tout autre endpoint MSN. Côté API mobile, appelé depuis MsnListScreen au chargement ; MsnChatScreen fait confiance à la session déjà initialisée et charge les messages directement.

Sécurité. Session TRIADE requise. Si des paramètres GET idpers et membre sont fournis, ils sont comparés aux valeurs de session — une divergence retourne 403 (protection cross-account). Deux requêtes PostgreSQL séparées au lieu d'un OR pour contourner un bug du driver PGSQL avec LOWER() OR.

1. id_pers + membre (chemin sûr) — lookup direct, met à jour l'email.
2. Rétrocompatibilité email — compte existant avec email @msn.triade, remplit id_pers/membre.
3. Auto-création — INSERT avec unique_id = abs(crc32($email)), résolution de collision par rand().

Télécharger une pièce jointe

Retourne le contenu d'une pièce jointe encodé en Base64, identifiée par son hash MD5. Le nom d'origine et le type MIME sont fournis pour permettre l'enregistrement et l'ouverture côté client.

Paramètres GET
ParamètreTypeRequisDescription
md5stringRequisHash MD5 du fichier (clé dans tria_piecejointe.md5, nom du fichier sur disque)

  "type": "application/pdf",    // type MIME

}
Sécurité : le paramètre md5 est restreint aux caractères hexadécimaux. Le chemin réel est vérifié avec realpath() pour prévenir toute traversée de répertoire. L'utilisateur doit être connecté ; l'entrée doit exister dans tria_piecejointe avec etat=1.
